| 属性 | 值 |
|------|-----|
| **文件** | [backtest.py](file:///home/james/Documents/Project/UniQuant/src/uniquant/hands/strategies/backtest.py) L321, [cost_model.py](file:///home/james/Documents/Project/UniQuant/src/uniquant/shared/cost_model.py) L26-27 |

| **工时** | 30 分钟 |
| **影响** | 2023.08.28~2023.12.31 期间回测多扣一倍印花税（千1 vs 万5） |

**当前代码** (backtest.py:321):
```python

    effective_sell = COMMISSION_PCT + STAMP_TAX_PCT_OLD  # 千1
```

**当前注释** (cost_model.py:26-27):
```python

STAMP_TAX_PCT_OLD: float = 0.001          # 千1 (pre-2024)  ← 注释错误
```

**修复**:

1. cost_model.py 注释修正 + 增加切换日期常量:
```python
STAMP_TAX_PCT: float = 0.0005             # 万5 (2023-08-28起)
STAMP_TAX_PCT_OLD: float = 0.001          # 千1 (2023-08-28前)
STAMP_TAX_CUTOFF_DATE = datetime.date(2023, 8, 28)
```

2. backtest.py 修复：**必须逐笔交易判断**，不能对整个回测期用一个税率。
   原有 `max_year < 2024` 的全局判断有两个问题：
   - 年份粒度错误（2023年8月28日而非2024年）
   - 全局判断错误（跨越切换日的回测会对所有交易用错误税率）

   正确做法是在 `_calculate_commission` 或交易执行时逐笔判断：
```python
import datetime as _dt
_STAMP_TAX_CUTOFF = _dt.date(2023, 8, 28)

def _get_stamp_tax(trade_date) -> float:
    """根据交易日期返回正确的印花税率"""
    if isinstance(trade_date, str):
        trade_date = _dt.date.fromisoformat(trade_date[:10])
    elif hasattr(trade_date, 'date'):
        trade_date = trade_date.date()
    return STAMP_TAX_PCT_OLD if trade_date < _STAMP_TAX_CUTOFF else STAMP_TAX_PCT
```

   然后在 `execute_buy`/`execute_sell` 中调用 `_get_stamp_tax(current_date)` 替代硬编码税率。

> ⚠️ **注意**: 原修复方案中 `any(date < cutoff for date in trade_dates)` 的全局 `any()` 判断是错误的——跨越切换日的回测会导致所有交易都用旧税率。必须逐笔判断。

**验证**: 构造跨越2023-08-28的回测（2023-07-01至2023-10-01），确认8月28日前用千1、之后用万5。

def _calculate_lppl(self, t, tc, m, w, a, b, c, phi):
    tau = tc - t
    result = np.full_like(t, np.nan, dtype=np.float64)
    valid = tau > 0

### P1-3: MemoryCacheBackend 线程安全

| 属性 | 值 |
|------|-----|
| **文件** | [backends.py](file:///home/james/Documents/Project/UniQuant/src/uniquant/shared/cache/backends.py) |
| **行号** | L48-98 |
| **严重度** | 🟡 MEDIUM |
| **工时** | 30 分钟 |

> ⚠️ **死锁风险**: 原修复方案中 `get` 方法在持有 `threading.Lock` 时调用 `self.delete(key)`，而 `delete` 也加了同一把锁，`threading.Lock` 不可重入，会导致**死锁**。必须使用 `threading.RLock` 或拆分内部无锁方法。

**修复**: 使用 `threading.RLock`（可重入锁）并在 `__init__` 中初始化：

```python
class MemoryCacheBackend(CacheBackend):
    def __init__(self, max_size: int = 1000):
        self.cache = {}
        self.access_times = {}
        self.max_size = max_size
        self.hits = 0
        self.misses = 0
        self._lock = threading.RLock()  # RLock 允许同一线程重入

    def _delete_unsafe(self, key: str) -> bool:
        """内部无锁删除，供已持锁的方法调用"""
        if key in self.cache:
            del self.cache[key]
            self.access_times.pop(key, None)
            return True
        return False

    def get(self, key: str) -> Optional[Any]:
        with self._lock:
            if key in self.cache:
                cache_item = self.cache[key]
                if (time.time() - cache_item["created_at"]) > cache_item["ttl"]:
                    self._delete_unsafe(key)  # 调用无锁版本，避免死锁
                    self.misses += 1
                    return None
                self.access_times[key] = time.time()
                self.hits += 1
                return cache_item["data"]
            self.misses += 1
            return None

    def set(self, key: str, value: Any, ttl: int = 3600) -> bool:
        with self._lock:
            if value is None:
                return False
            if len(self.cache) >= self.max_size:
                self._evict_oldest()
            self.cache[key] = {"data": value, "ttl": ttl, "created_at": time.time()}
            self.access_times[key] = time.time()
            return True

    def delete(self, key: str) -> bool:
        with self._lock:
            return self._delete_unsafe(key)
```

### P1-7: compute_rolling_mdd 向量化

| 属性 | 值 |
|------|-----|
| **文件** | [drawdown_analyzer.py](file:///home/james/Documents/Project/UniQuant/src/uniquant/risk/drawdown_analyzer.py) |
| **行号** | L88-100 |
| **严重度** | 🟡 MEDIUM |
| **工时** | 1 小时 |

**源码核实**: 第95-100行确认使用 Python `for i in range(window-1, n)` 循环，非向量化。`compute_rolling_mdd` 方法本身无 docstring，"零 iterrows"声明无法在此方法中验证（可能在其他方法）。

> ⚠️ **原修复方案逻辑错误**: `np.maximum.accumulate(windows, axis=1)` 给出的是每行的累积最大值，取最后一列得到窗口内最大值，但这不等于滑动窗口最大回撤。最大回撤需要对每个窗口内的每个时间点计算 `(price - running_max) / running_max`，然后取最小值。

**正确的向量化修复**:
```python
@staticmethod
def compute_rolling_mdd(equity: np.ndarray, window: int) -> np.ndarray:
    n = len(equity)
    result = np.zeros(n, dtype=np.float64)
    if n < window:
        return result
    from numpy.lib.stride_tricks import sliding_window_view
    windows = sliding_window_view(equity, window)  # shape: (n-window+1, window)
    # 对每个窗口，计算累积最大值，再算回撤
    running_max = np.maximum.accumulate(windows, axis=1)  # shape: (n-window+1, window)
    drawdowns = (windows - running_max) / np.maximum(running_max, 1e-10)  # 负值
    result[window - 1:] = -np.min(drawdowns, axis=1)  # 取每窗口最大回撤（正值）
    return result
```

> 注：`np.maximum.accumulate(windows, axis=1)` 对每行（每个窗口）求累积最大值，`drawdowns` 是每个时间点相对于窗口内历史最高点的回撤，`np.min(drawdowns, axis=1)` 取每窗口最大回撤（最负值），取负号转为正值。逻辑正确。

## 八、关键决策点

### 决策 1: LimitScalar 方向

**源码核实**: 代码中**不存在** `0.10 / limit_pct` 公式。`sizer.py:80` 的 T+1 隔夜风险惩罚是硬编码固定值 `1.2`，`classifiers.py:246` 的 `limit_pct` 仅用于涨跌停检测，不涉及惩罚系数。

**结论**: 此决策描述的是一个**尚未实现的功能设计**，而非现有代码的修复。如果未来要实现动态惩罚系数，公式方向 `limit_pct / 0.10` 是正确的（科创板 ±20% → 惩罚 2.0，ST ±5% → 惩罚 0.5）。当前无需修复，可列入 Phase 3 功能增强。

### 决策 2: 幽灵导入修复是否需要

**源码验证结论**: `services/__init__.py` 和 `brain/lppl/__init__.py` 的幽灵导入问题**已被修复**。AGENTS.md 中的描述过时。

**建议**: 更新 AGENTS.md，删除"8 个幽灵导入"和"7 个幽灵导入"的描述，节省 Phase 0.0 的 1-2 天工期。

### 决策 3: `not LimitStatus` 是否为 Bug

**源码验证结论**: **不是 Bug**。`_check_limit_constraint` 返回 `bool`，不是 `LimitStatus`。REVIEW3 的结论有误。

**建议**: 不修复此问题。但建议重构 `_check_limit_constraint` 直接使用 `LimitStatus.can_buy`/`can_sell`，消除冗余逻辑。
