## 四、降级与异常处理

### 4.1 数据湖不可用

如果 `ls data/lake/*.parquet` 失败:

| Phase | 降级方案 | 影响 |
|---|---|---|
| C | 使用 `tests/fixtures/*.parquet` + 构造 OHLCV DataFrame | C1/C3/C4 标记"基于测试子集"，C2/C5/C6/C7 不受影响 |
| D | 使用 DataFetcher 缓存 + DataService 测试模式的 mock 数据 | D2 全市场分布降级为样本分析（~100 票），D1/D3-D7 不受影响 |
| G | 基于 D 的样本数据做 profiling | G1/G3/G4 仅限样本规模，G2 跳过 |
| E/F | 基于降级 D 的输出 | 结论附加"样本限制"标注 |

### 4.2 海量问题导致报告膨胀

如果任一 Phase 发现 >50 项问题:

- 报告只记录 Top-20（按严重级别排序）
- 其余问题汇总到 `docs/reanalysis/XX_overflow_issues.md`
- J 阶段统一筛选

### 4.3 任何 Phase 阻塞

如果 Phase X 报告无法在预估工时内完成:

- 确定已完成子项和未完成子项
- 将未完成子项的严重级别标注
- 进入 J/K 时标记为"部分完成"
- 在最终路线图中安排后续补做
