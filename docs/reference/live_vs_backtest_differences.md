# 回测与实盘差异分析

> 本文档系统梳理 UniQuant 回测引擎（`UnifiedBacktestEngine` + `UnifiedMatchingEngine`）与 A 股实盘交易之间的已知差异，量化每项差异对回测结果的影响方向和幅度，并提供针对性的调整建议。

---

## 1. 撮合引擎近似假设

### 1.1 集合竞价未建模

**回测现状：** 信号在 T 日收盘后生成，挂单在 T+1 日以 **开盘价** 直接成交（`unified_engine.py:180`）。开盘价的生成过程（9:15-9:25 集合竞价）被完全跳过。

```python
# unified_engine.py:180
exec_price_raw = opens[idx]  # 直接取开盘价，不考虑集合竞价撮合过程
```

**实盘差异：**
- 集合竞价阶段存在价格发现过程，9:20-9:25 不可撤单，大额订单可能影响开盘价
- 开盘价是集合竞价撮合结果，不一定是即时可成交价格
- 实盘中如果持仓较大，卖出时可能对开盘价产生冲击（尤其小盘股）

**影响评估：** 轻度低估执行风险。对于流动性好的大盘股（日均成交 > 5 亿），开盘价成交假设合理；对于小盘/微盘股，实际成交价可能偏离开盘价。

### 1.2 T+1 实现方式（序数比较 vs 中登结算）

**回测现状：** 使用日历日序数比较判断 T+1 约束（`unified_matching_engine.py:220-235`）。通过 `buy_dates` 与 `timestamps` 的 `toordinal()` 差值判断是否满足 T+1：

```python
# unified_matching_engine.py:222-235
b_td = self.trade_calendar.is_trading_day(b_ts)
c_td = self.trade_calendar.is_trading_day(c_ts)
if not b_td or not c_td:
    t1_violation[i] = True
elif c_ts.toordinal() <= b_ts.toordinal():
    t1_violation[i] = True
else:
    next_td = self._next_trading_day(b_ts)
    if c_ts.toordinal() < next_td.toordinal():
        t1_violation[i] = True
```

此外 `UnifiedBacktestEngine.run()` (`unified_engine.py:212`) 也在主循环中维护 `buy_date` 进行 T+1 校验。

**实盘差异：**
- 中登结算（ChinaClear）在 T 日收盘后完成证券过户，实际交割时间约 T 日 16:00-18:00
- 回测的序数比较忽略了节假日间隔超过 1 天的情况（如春节前买入、春节后卖出的 T+1 判断仍然正确，但回测无法模拟休市期间的隔夜风险敞口）
- 回测中 T+1 拒绝后订单直接丢弃；实盘中投资者可以选择次日再卖

**影响评估：** 影响轻微。序数比较 + 交易日历在绝大多数情形下与真实 T+1 等价。唯一差异在于：回测中拒绝卖出的订单 **永远消失**，而实盘中可以重新挂单。

### 1.3 部分成交未建模

**回测现状：** 全成交或全拒绝，没有中间状态：

```python
# unified_matching_engine.py:178
shares_adj = np.where(limit_rejected, 0, shares_adj)

# unified_engine.py:500-502
shares = (shares_requested // lot_size) * lot_size
if shares <= 0:
    return None, cash_available
```

**实盘差异：**
- 大额订单在薄流动性下可能部分成交（如挂 10000 股只成交 3000 股）
- 部分成交后剩余资金释放，可在同一交易日再次使用
- 涨跌停封板时，排队的订单可能部分成交（取决于排队位置）

**影响评估：** 中度低估实际执行灵活性。部分成交在 A 股市场并不罕见（尤其小盘股、ST 股、涨跌停板附近）。回测的"全或无"模型会低估实盘中部分成交带来的资金利用率。

### 1.4 涨跌停封单量未建模

**回测现状：** 仅检查价格比例是否达到涨跌停阈值：

```python
# unified_matching_engine.py:96-103
board_types = np.array([get_board_type(s) for s in symbols])
for board_type, (up_r, down_r) in MarketConstants.LIMIT_RATIO.items():
    board_mask = board_types == board_type
    mask = board_mask & valid
    is_limit_up |= mask & (price_ratios >= up_r - tol)
    is_limit_down |= mask & (price_ratios <= down_r + tol)
```

**实盘差异：**
- 涨停时买入订单能否成交取决于排队位置和封单量——涨停打开（成交量放大）可能成交
- 跌停时卖出同理——如果跌停被撬开（买单涌入），卖单可能成交
- 回测中涨跌停是二元的：到了阈值就全部拒绝；实盘中封单量/成交量是连续变量

**影响评估：** 中度高估涨跌停日的执行阻力。回测直接拒绝所有涨停买入/跌停卖出，但实盘中：
- 涨停打开（封单量小，成交量放大）时仍可能买入
- 跌停打开时仍可能卖出
- 对于策略，这可能高估涨跌停日的执行成本，尤其在小盘股（封单量通常较小）

### 1.5 开盘价成交假设

**回测现状：** 所有订单在 T+1 日的 **开盘价** 执行（`unified_engine.py:180`），盘中无法挂单：

```python
# unified_engine.py:178-236
# Step 1: Execute pending order at T+1 open
if pending_order is not None:
    exec_price_raw = opens[idx]
    # ... execute at open
```

**实盘差异：**
- 实盘可以选择在盘中任何时间点挂单（如挂限价单、用算法交易拆单）
- 开盘价可能不是最优执行价格（如大幅低开时卖出会放大亏损）
- 实盘可以通过选择时间段来优化执行（如下午盘拉升时卖出）

**影响评估：** 轻度至高估执行成本（取决于策略类型）。对于低频策略（月频调仓），开盘价假设影响很小；对于高频/日频策略，开盘价的日内波动可能导致实际执行价格与回测的系统性偏差。

## 2. 成本模型差异

### 2.1 佣金：万 3 + 最低 5 元 vs 实际券商差异

**回测现状：**

```python
# cost_model.py:29, 32
COMMISSION_PCT: float = 0.0003    # 万3
MIN_COMMISSION: float = 5.0       # 单笔最低5元

# unified_matching_engine.py:162
commissions = np.maximum(values * self.commission_rate, self.min_commission)
```

**实盘差异：**

| 项目 | 回测默认值 | 实盘常见区间 | 影响 |
|------|-----------|-------------|------|
| 费率 | 万 3 | 万 1.5 ~ 万 3（大资金可低至万 1） | 大资金可能高估成本 |
| 最低佣金 | 5 元 | 5 元（部分互联网券商取消最低佣金） | 小单可能高估成本 |
| ETF 佣金 | 万 3 | 万 0.5（ETF 有政策优惠） | ETF 回测需调整 |

**影响评估：** 轻度高估交易成本。对于单笔 > 16.7 万元的交易（50000 / 0.0003），最低佣金 5 元不再生效，实际影响取决于券商费率谈判。建议在 `CostConfig.from_env()` 或 `CostConfig.from_yaml()` 中设置真实费率。

### 2.2 印花税：仅卖方万 5 vs 未来可能的调整

**回测现状：**

```python
# cost_model.py:30, 44-45
STAMP_TAX_PCT: float = 0.0005       # 万5 (2023-08-28起)
STAMP_TAX_PCT_OLD: float = 0.001    # 千1 (2023-08-28前)

def get_stamp_tax_pct(trade_date: datetime.date) -> float:
    return STAMP_TAX_PCT if trade_date >= _STAMP_TAX_CUTOFF else STAMP_TAX_PCT_OLD
```

**实盘差异：**
- 印花税历史上多次调整（2008 千 1 → 2023 减半至万 5 → 未来可能进一步降低或取消）
- 仅卖方征收的特征保持不变
- 2024 年曾有政策讨论将印花税转由中央与地方分享，但未改变征收方式

**影响评估：** 取决于回测周期和假设。系统正确处理了 2023-08-28 的税率切换。如果未来税率继续下调，当前回测会 **高估** 卖出成本。对于长周期回测（跨 5 年以上），建议使用 `get_stamp_tax_pct()` 的历史感知功能。

### 2.3 过户费：0.001% vs 实际中登费率

**回测现状：**

```python
# cost_model.py:34
TRANSFER_FEE_PCT: float = 0.00001   # 万0.1

# cost_model.py:48-50
def _has_transfer_fee(symbol: str) -> bool:
    return symbol.startswith("60")   # 仅沪市
```

**实盘差异：**
- 2022 年 11 月起，深市（00/30 开头）也开始收取过户费万 0.1
- 此前深市免收过户费
- 系统代码中 `_has_transfer_fee()` 仅识别沪市，未更新深市规则

**影响评估：** 轻微低估深市成本。万 0.1 的过户费在总成本中占比极小（深市卖出总费率万 8 中仅占 0.00125），但深市代码路径是 **错误地免收了过户费**。这是一个 bug，影响可忽略但应修复。

### 2.4 滑点：固定万 5 + 市场冲击 vs 动态滑点

**回测现状（双重滑点模型）：**

`UnifiedMatchingEngine.compute_execution_prices()` (`unified_matching_engine.py:68-77`)：

```python
vol_ratios = np.where(
    (avg_daily_volumes > 0) & (volumes > 0),
    np.minimum(volumes / np.maximum(avg_daily_volumes, 1e-8), 1.0),
    0.0,
)
impact = np.minimum(0.001 * np.sqrt(vol_ratios), 0.02)
total_slip = self.slippage_rate + impact
```

`UnifiedBacktestEngine._calc_slippage()` (`unified_engine.py:447-462`) 使用 `trade_volume / avg_daily_volume` 计算：

```python
ratio = trade_volume / avg_daily_volume
impact = min(0.001 * (ratio ** 0.5), 0.02)
```

`DefaultSlippage` (`slippage_model.py:14-17`) 返回固定值，`DynamicSlippage` (`slippage_model.py:20-28`) 有流动性/波动率感知能力。

**实盘差异：**

| 场景 | 回测假设 | 实盘实际 | 影响方向 |
|------|---------|---------|---------|
| 大单（> 日均成交 5%） | 冲击上限 2% | 实际冲击可达 3-5% | 低估成本 |
| 小单（< 日均成交 0.1%） | 冲击接近 0 | 实际冲击约 0.01-0.02% | 轻微高估 |
| 盘中急涨/急跌时 | 冲击基于成交量比率 | 实际滑点远大于模型 | 低估成本 |
| 开盘/收盘时段 | 无区分 | 流动性低，滑点大 | 低估成本 |
| SlippageModel.DynamicSlippage | 有时间衰减 | 但 `_market_impact` 使用硬编码 10 亿流动性 | 不准确 |

**影响评估：** 中度。市场冲击的平方根模型是学术界标准模型，在大单时是合理的近似。但缺少：
1. 时间维度的滑点差异（上午/下午开盘时段）
2. 不同市场状态的滑点差异（趋势市 vs 震荡市）
3. 拆单算法模拟（实盘大单会拆成多个小单，减小冲击）

## 3. 仓位计算差异

### 3.1 T+1 惩罚系数 1.2 的保守程度

**回测现状：**

```python
# sizer.py:84
self.market_penalties = {"CN": 1.2, "US": 1.0, "HK": 1.0}

# sizer.py:161-167
penalty = self.market_penalties.get(market, 1.0)
effective_risk_pct = self.risk_pct * self.kelly_fraction if self.kelly_fraction is not None else self.risk_pct
max_loss_allowed = safe_round(self.capital * effective_risk_pct, PrecisionConstants.PRICE_DECIMALS)
shares = safe_divide(max_loss_allowed, risk_per_share * penalty, 0)
```

**实盘差异：**
- 1.2 倍的惩罚意味着单位风险被放大 20%，目标仓位相应降低 16.7%（1 - 1/1.2）
- 这个系数是基于经验的固定值，未根据个股波动率、板块特征动态调整
- 实盘中隔夜风险的实际大小取决于：持仓标的的波动率、市场状态、是否有突发事件

**影响评估：** 中度偏保守。1.2 倍惩罚在正常市况下是合理的安全边际。但在极端行情（如 2015 年股灾、2024 年初流动性危机）中，隔夜跳空幅度可达 10%+，1.2 倍惩罚可能不足。建议根据策略持仓周期和标的波动率动态调整。

### 3.2 Kelly 公式在实盘中的调整

**回测现状：**

```python
# sizer.py:86-95
def calculate_kelly(win_rate: float, avg_win: float, avg_loss: float) -> float:
    ...
    kelly = (b * win_rate - q) / b
    return max(0.0, min(kelly, 1.0))
```

**实盘差异：**
- 全 Kelly 公式在实盘中几乎不可用（过高杠杆，过大的回撤风险）
- 标准做法是使用分数 Kelly（1/4 或 1/3 Kelly）
- 系统支持 `kelly_fraction` 参数，但默认行为是使用 `risk_pct`（5%）作为等风险权重，不调用 Kelly
- 实盘中 Kelly 参数（胜率、平均盈亏比）的估计误差可能导致仓位偏差

**影响评估：** 取决于是否使用 Kelly。默认的 5% 风险敞口 + 1.2 倍惩罚约等效于 4.17% 有效风险敞口，对于大部分策略是合理保守的。如果启用 Kelly，需注意参数估计误差。

                 max_single_sector_pct=0.20):

**实盘差异：**

- 没有行业限制，多标的策略可能无意中集中到同一行业（如全部持有银行股或白酒股），产生伪分散
- 这会高估组合的分散化效果和夏普比率

**影响评估：** 中度高估组合分散效果。对于多标的回测，应手动检查持仓的行业分布，或待该功能实现后再正式使用。

## 4. 数据质量影响

### 4.1 前复权数据的未来数据偏差

**回测现状：** 数据通过 `DataFetcher.fetch_stock_daily(..., adjust="qfq")` 获取前复权数据（见 `backtest.md:109`）。

**前复权（QFQ）的原理问题：**
- 前复权使用 **未来的** 除权除息信息来调整 **过去的** 价格
- 例：某股今日 10 送 10，前复权会将所有历史价格除以 2
- 在 T 日的回测中，使用的价格已经包含了 T+N 日的除权信息 → 产生未来函数

**具体影响：**
- 历史价格被系统性压低 → 涨幅计算可能失真
- 技术指标（均线、RSI、布林带）在除权除息日前后的形态被扭曲
- 止损价在除权后可能不正确（前复权后的止损价低于实际历史止损价）

**减轻措施：**
- 回测中 `_prepare_dataframe` 使用 `pre_close` 计算涨跌停比例，但这从前复权数据中推断，仍然存在偏差
- 更好的做法：使用后复权（不复权原始数据 + 手工处理除权除息）

**影响评估：** 中度。前复权在回测中最关键的偏差在于：它使得过去的价格看起来更低，导致回测中的涨幅看起来比实际更大。这个偏差对于长周期（5 年+）回测尤其显著。高频换手策略受干扰更大（技术指标更敏感）。

### 4.2 停牌股处理

**回测现状：**

```python
# unified_engine.py:186-188
if vol <= 0:
    logger.debug(f"停牌拒绝: {date_key} volume=0")
    pending_order = None
```

**实盘差异：**
- 回测中停牌日订单被丢弃，下一个交易日重新检查是否有信号
- 实盘中停牌股无法交易，复牌时通常有连续涨停/跌停，但回测无法模拟这种"流动性冲击"
- 回测的简单跳过停牌日假设复牌后可以立即按开盘价成交，但实盘中复牌首日常有涨跌停限制

**影响评估：** 轻度高估流动性。停牌复牌后的流动性冲击是实盘中的主要风险之一，回测的简化处理可能高估停牌股的交易能力。

### 4.3 除权除息日缺口

**回测现状：** 前复权数据抹平了除权除息日的价格跳空。回测中如下流水线处理:

```
QFQ 数据 → 回测引擎 → 信号生成 → 开平仓
```

**实盘差异：**
- 除权除息日在实盘中是真实的价格跳空（通常向下 5-30%）
- 前复权将这一跳空均匀摊薄到历史所有 bar，导致：
  - 回测中的"回撤"被低估（因为除权日的跳空被吸收了）
  - 止损逻辑在除权除息日前后的表现与实盘不一致
  - 现金分红部分在回测中无法体现（持仓市值直接减少，无现金到账）

**影响评估：** 中度。对于长线持有策略（持有期 > 6 个月），除权除息的影响累积较大。建议在关键回测中使用 **后复权 + 手工处理分红** 进行验证。

## 5. 量化影响评估

### 5.1 差异汇总表

| # | 差异项 | 影响方向 | 严重程度 | 主要影响策略类型 | 建议 |
|---|--------|---------|---------|----------------|------|
| 1.1 | 集合竞价未建模 | 低估执行风险 | 轻度 | 日内/高频策略 | 对低频策略可忽略 |
| 1.2 | T+1 序数比较 vs 中登结算 | 轻微 | 极轻微 | 所有策略 | 可忽略，假设合理 |
| 1.3 | 部分成交未建模 | 低估资金利用率 | **中度** | 小盘股策略、大单策略 | 建议对日成交 < 5000 万的标的单独验证 |
| 1.4 | 涨跌停封单量未建模 | 高估执行阻力 | **中度** | 涨停板敢死队策略、事件驱动策略 | 涨跌停日建议手动检查封单量 |
| 1.5 | 开盘价成交假设 | 估值偏差 | 轻度 | 日频/低频策略 | 中长期偏差趋于零 |
| 2.1 | 佣金万 3 vs 实际券商差异 | 高估成本(大资金)/低估(小单) | 轻度 | 高频换手策略 | 使用 `CostConfig.from_yaml()` 设置真实费率 |
| 2.2 | 印花税未来可能调整 | 取决于未来政策 | 轻度 | 所有策略 | 政策敏感时做税率敏感性分析 |
| 2.3 | 过户费深市错误免收 | 低估深市成本 | 极轻微 | 深市重仓策略 | 建议修复 `_has_transfer_fee()` 中深市规则 |
| 2.4 | 滑点模型简化 | 大单低估/小单高估 | **中度** | 大单策略/小盘股策略 | 回测后做滑点敏感性分析 |
| 3.1 | T+1 惩罚系数 1.2 | 偏保守 | 中度 | 高波动策略 | 极端行情下压力测试 |
| 3.2 | Kelly 公式参数不确定性 | 取决于使用方式 | 中度 | 使用 Kelly 的策略 | 建议使用分数 Kelly（1/4 或 1/3） |
| 3.3 | 行业集中度未实现 | **高估分散效果** | **中度** | 多标的组合策略 | 实现前手动检查行业分布 |
| 4.1 | 前复权未来数据偏差 | 高估收益 | **中度** | 长周期策略、高频策略 | 用后复权验证关键结果 |
| 4.2 | 停牌股简化处理 | 高估流动性 | 轻度 | 小盘股策略 | 检查复牌日后的实际表现 |
| 4.3 | 除权除息日缺口 | 低估回撤 | 中度 | 长线持有策略 | 长周期回测建议检查红利再投资影响 |

### 5.2 对策略排序影响

| 策略类型 | 受哪些差异影响最大 | 回测结果可靠性 |
|---------|------------------|--------------|
| **低频蓝筹策略**（年换手 < 2x，偏好大盘股） | 4.1 前复权偏差、4.3 除权除息 | **较高** 前复权对蓝筹的偏差最小，流动性差异较小 |
| **小盘股策略**（持有市值 < 50 亿） | 1.3 部分成交、1.4 封单量、2.4 滑点 | **较低** 应大幅提高滑点假设，或用后复权验证 |
| **高频策略**（日频以上） | 1.1 集合竞价、1.5 开盘价成交、2.4 滑点 | **较低** 回测无法模拟日内微观结构 |
| **多标的组合策略** | 3.3 行业集中度、3.1 惩罚系数 | **中等** 需手动检查过拟分散 |
| **事件驱动策略**（ST、复牌、分红） | 1.4 封单量、4.2 停牌、4.3 除权除息 | **低** 回测中的事件模拟最弱，需格外谨慎 |

### 5.3 总体建议

**高优先级（显著影响回测结论，务必处理）：**

1. **前复权偏差（4.1）**：对所有策略进行后复权验证，或至少在同一回测中使用不复权数据 + 手工处理分红股。这是最大且最隐蔽的回测偏差来源。
2. **行业集中度（3.3）**：在使用 `PortfolioSizer` 前，手工检查持仓的行业分布。回测中的"多标的分散"可能是伪分散。
3. **滑点校准（2.4）**：对策略持仓的典型换手量，使用实际日均成交量的比例来校准滑点。公式：`滑点 = max(万5, min(0.001 × sqrt(换手率/日均成交), 0.02))` 是一个合理的安全边界。

**中优先级（影响定性判断）：**

4. **部分成交（1.3）和封单量（1.4）**：小盘股策略应增加 10-20% 的冲击成本 buffer。
5. **佣金设置（2.1）**：通过 `CostConfig.from_yaml()` 设置真实券商费率。
6. **印花税敏感性（2.2）**：在政策敏感期做买入/卖出成本的敏感性分析。
7. **过户费修复（2.3）**：修改 `cost_model.py` 中深市过户费规则。

**低优先级（可忽略，或影响相互抵消）：**

8. T+1 序数比较 vs 中登结算（1.2）——合理近似
9. 集合竞价未建模（1.1）——对日频以上策略影响可忽略
10. 开盘价成交假设（1.5）——中长期均值回归

### 5.4 一个可操作的验证流程

```
1. 使用默认参数运行回测 → 得到结果 R1
2. 后复权数据验证 → 运行同样的策略在后复权数据上 → R2
   - 如果 R1 与 R2 的收益率差异 > 20%，说明前复权偏差显著
3. 滑点敏感性 → 滑点从万 5 -> 千 2 做参数扫描 → R3
   - 如果 10% 滑点变化导致策略排名改变，策略依赖微小的成本优势
4. 行业分布随机化 → 将同一策略替换标的为同行业其他股 → R4
   - 如果 R4 与 R1 的夏普比率差异 > 0.3，说明存在行业集中风险
5. 不可模拟风险标注 → 在策略报告中标注以上差异中哪些影响最大
```

> **核心原则：** 回测是策略的 **必要条件** 而非 **充分条件**。回测中表现最好的策略，在实盘中可能因为本文档所述的差异而表现不佳。理解差异的方向和幅度，比追求回测指标的极致更重要。
