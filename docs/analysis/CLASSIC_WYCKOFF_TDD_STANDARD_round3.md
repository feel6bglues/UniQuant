## R3-01（交易员+算法·Red）: 标准缺少 A 股微观结构适配层

**声明**: 整个标准隐含前提是"经典 Wyckoff 在美股足够有效"。

**A 股特异性未被覆盖**:

| 特征 | 对 Wyckoff 的影响 | 标准中有？ |
|------|-------------------|:--------:|
| T+1 交割 | Spring 后第二天不能卖——Spring 信号被锁 1 天 | ❌ |
| ±10%/20% 涨跌停 | BC/SC/Spring 的 spread 被截断，P&F 列失真 | ❌ |
| 集合竞价开盘 | 高开/低开缺口扭曲 P&F 的跳空计数 | ❌ |
| 科创板/创业板 20% 涨跌 | 不同板振幅差异 2x，box_size 自适应需区分 | ❌ |
| 国家队/机构大单申报披露 | 信息披露导致行为与美国市场不同 | ❌ |
| 流通市值小导致高波动 | 振幅是美股的 2-3 倍，TR 界定需调整 | ❌ |
| 分红/送股后复权跳跃 | P&F 上的假 gap——数据需要前复权 | ❌ |

**建议**: 增加 §10 **市场适配层**。上海主板/深圳主板/科创板/创业板分别定义 box_size 基准和涨跌停截断规则。T+1 影响在 Spring 检测后增加 1 天的冷却观察期。

## R3-02（程序员+架构师·Red）: 没有定义 Phase 的"不可判定"阈值

**声明**: PH-01~10 定义了 10 个 Phase 的测试条件。

**问题**: 实际数据中，大概率会出现"部分条件满足，部分不满足"的情况。标准没有定义：
- 满足多少条件才算 Phase？（如 Phase B: 需要 4 个条件中满足 ≥3 个？还是 2 个条件是必须的——SC + 连续 ST——可以不用量能萎缩？）
- Phase 置信度与条件满足比例的关系？

**建议**: 每个 Phase 条件定义必须附带：
```
PH-02 (Phase B Accumulation):
  Required (must pass):
    - SC 已经被检测到
    - 至少 2 次 ST 事件
  Optional (weighted):
    - 量能持续萎缩 (weight=0.4)
    - 价格在 TR 下沿 10% 内震荡 (weight=0.3)
    - 下边界成交量递减 (weight=0.3)
  Pass threshold: required_passing=2个中2个, weighted_score >= 0.6
  Confidence:
    - >=0.9 → "confirmed"
    - 0.6-0.9 → "probable"
    - <0.6 → "not_detected"
```

## R3-03（交易员+Python·Red）: 已知模式测试集 KN-01 的时间跨度与实际 A 股数据不兼容

**声明**: KN-01 使用"2018-2020 沪深 300"作为经典 Accumulation 测试数据。

**问题**:
1. 2018 全年下跌（贸易战），2019 反弹，2020 新冠后涨——这不是经典 Wyckoff Accumulation（横盘积累），是 V 型反转
2. 经典 Accumulation 需要 12-24 个月的 TR 横盘——A 股很少有这种模式
3. A 股的 Accumulation 更接近 Markdown→TR→Markup，而非教科书 SC→ST→Spring

**建议**: 将 KN-01 替换为:
- KN-01a: 2015 年 8 月-2016 年 12 月（熔断后的底部 TR + 2017 价值牛市开端）
- KN-01b: 2018 年 12 月-2019 年 3 月（贸易战底部的快速 V 反——这是 A 股独有的 WYckoff 模式：无 SC 无 ST，直接 PS→SOS）
- KN-01c: 2022 年 10 月-2023 年 3 月（疫情放开底——同样是 V 反）

## R3-04（算法工程师·Red）: 合成数据生成器的反证价值没有定义

**声明**: 标准要求合成数据生成器输出可验证事件序列，但没有要求**对抗性测试数据**。

**问题**: 合成数据应包含：
1. Phase 模式的正向样本（标准定义）
2. **接近但不完全匹配的事件序列**（例如 Spring 条件达到 3/4，但缺量能萎缩）
3. **随机 OHLCV 数据**——应全部返回 UNKNOWN（作为 FPR 基线）
4. **已知假模式**——看起来像 Spring 的随机波动。检测器必须识别为 NON-Spring

**建议**: 在合成数据测试中增加：

```
Adversarial Test Set:
  ─ Phase 模式完整序列: 10 个 accum + 10 个 distrib + 10 个 markup + 10 个 markdown
  ─ 随机 OHLCV (GBM): 100 个序列，预期 UNKNOWN 率 >= 95%
  ─ 接近但不完全的序列: 50 个 (每个 Phase 模式有 20% 条件缺失)
  ─ 已知假模式: 20 个 (价格特征像 Spring 但量能不符合)
```

## R3-05（架构师+程序员·Red）: 没有性能预算

**声明**: 标准定义了大量测试和覆盖指标，但没有给任何性能预算。

**问题**:
- 5000 只股票的 P&F 构建 + Event 检测 + MTF 裁决不能在 1 秒完成
- P&F 的增量更新 vs 全量重建的性能差异可能 100x
- 没有实时回测的性能底线，设计时无法判断哪些组件需要优化

**建议**: 增加性能预算：

```
Performance Budget (per ticker):
  P&F Builder:                 <= 10ms (增量更新) / <= 50ms (全量重建)
  Event Detection (10 events):  <= 5ms
  Volume Signature (6 sigs):    <= 3ms
  Phase Resolution:             <= 2ms
  Multi-Timeframe:              <= 2ms
  Relative Strength:            <= 2ms
  Counterfactual:               <= 5ms
  ─────────────────────────────────────────
  Total per ticker:             <= 29ms
  5000 tickers:                 <= 145s (2.4min)

Bottleneck Warning:
  P&F Builder > 50ms → 需要增量更新架构
  Event Detection > 10ms → 需要向量化或 Numba
```

## R3-06（交易员·Red）: TA 序列与 Wyckoff 的冲突处理未定义

**声明**: 标准假设 Wyckoff 信号是独立的。实际上交易员同时使用 MACD、RSI、布林带等指标。

**问题**: Wyckoff Spring 同时 RSI 底背离 → 买入信号 +1.5 权重。
Wyckoff Spring 但 RSI 超买 → 买入信号 -0.5 权重（矛盾信号）。

**建议**: 在 L4 反事实层增加 **TA 信号集成网关**：
```
TA Integration:
  - RSI(14) < 30 + Wyckoff Spring → "strong_buy" (权重 +0.5)
  - MACD 金叉 + SOS → "confirmed_breakout" (权重 +0.3)
  - Volume EMA12 > EMA26 金叉 + BC → "distribution_warning" (权重 -0.3)
  - 任意 TA 指标与 Wyckoff 矛盾时 → "conflicting" (降权 0.3)
```
