## 一、修改基础与逻辑（方案为什么这样改）

### 1.1 三层修改依据链

每个改动都追到一条判定链，不做无依据的改动：

| 方案改动 | 上游判定 | 数据证据 |
|---|---|---|
| P0: distribution 分支允许 leader 做多 | "alpha 轴错位，真信号在 `leader∧distribution`" | 三窗 +5.85/+4.09/+9.07，MWU p<0.01 全三窗 |
| P0: 只给"轻仓试探"不满仓 | "leader 高换手 + 中位层面胜率约半" | 30 日重合率 15.9%；exc>0 占比 46-54% |
| P0: RS 计算前置 | 顺序缺陷（step5 在 RS 之前执行） | engine.py:441 vs 459 |
| P1: spring 降为观察 | "spring 证伪、消解 alpha" | leader×spring −5.57/−7.50 |
| P1: 结构分置信通路关闭 | "结构分离弃用，leader 内高分是劣势" | IC 三窗翻转；8.00 vs 5.07 |

### 1.2 逻辑推演主链

```
方法论判定: 状态≠方向≠排序 (成立)
   └─► α 轴 = 派发期相对强弱 (leader∧distribution)
          └─► 但生产引擎 _step5 把 DISTRIBUTION 硬编码"空仓观望"
                 └─► 唯一正超额信号被引擎空仓吃掉 (W3: 321/321 全空仓)
                        └─► 修复 = 在 direction 派生层叠加经实证的 RS=leader 电子门
                                  (不动相位判定器，只动方向合成)
```

关键逻辑点：
1. **不动相位判定器、只改方向合成**——与 accumulation 降档/假突破 gate 同构、正交。
2. **RS 前置是纯顺序修正**（先算后用），默认 None 语义不变。
3. **flag 门控 A/B 可回退**——沿用 `_accumulation_downgrade` 已验证模式。
4. **只做多、不开空、最高轻仓**——不违反 A股铁律与经典 distribution 减仓直觉。

### 1.3 代价与验证结构
- 修改面：`_step5` 1 个分支 + RS 前置 + 1 个 config + 新增测试文件（~10 用例）。
- 不触碰：相位判定、事件检测、markdown/涨跌停/假突破 gate。
- 验证：TDD（RED→GREEN）、163 回归、三窗复扫验证候选池不再全空仓。

## 二、红蓝对抗

### 2.1 红方（攻击方案）

**R1 — 三窗独立性不足（最重）**：三窗 fwd 窗口首尾相接但不重叠（W1~06-02/W2~05-01/W3~07-04），但都在**同一行情段**（2026 上半年）重采样，非三个独立 regime；均值显著主要靠右尾。把"三窗显著"说成"稳健 alpha"过强。→ 蓝方：方案已用"轻仓试探 + N 期确认"内置缓冲，但措辞确应降级。

**R2 — 机制黑盒 / 动量皮肤嫌疑**：为什么"派发期比大盘走得强"就该涨？死不解释。若只是 20d 相对动量，Wyckoff 相位标签是多余的皮肤。→ **这是本轮对抗的最高风险点**。

**R3 — 中位胜率低**：exc>0 占比 W2 仅 46.3%，靠右尾平均撑起。方案未注明"低胜率高赔率"属性。

**R4 — P1 spring 改动与既有 P0 传导（15/36 spring→轻仓）冲突**：直接降级会行为倒退，需连带回归。

**R5 — P0 验收依赖 P2 的 E4 工具**：顺序有循环依赖，E4 应前移。

### 2.2 蓝方（辩护方案）

**B1 — 不违反任何 A股铁律与既有 gate**：markdown 禁多、涨跌停、假突破、accumulation 降档全保留；新分支正交、最高轻仓试探。
**B2 — 修改面最小**：只改 1 个分支 + 顺序 + config，回归面窄、flag 可回退。
**B3 — 治的是"唯一已证问题"**：上层判定已证 leader∧dist 是三窗唯一稳健正超额且引擎当前 100% 标空仓——这是最优修复点而非可选优化。

### 2.3 决定性实验（红方 R2 兑现验证）

纯动量对照：从数据湖计算各 as-of 前 20d `(个股−指数)` 相对动量，对比 `relmom_top10`（纯动量池）vs `leader∧distribution`：

| 窗口 | IC(relmom) | relmom_top10 | ld∧dist | 增量(lddist−rmtop) |
|---|---|---|---|---|
| W1 | +0.172*** | +9.51% | +5.85% | **−3.66pp** |
| W2 | −0.078*** | +2.84% | +4.09% | **+1.24pp** |
| W3 | +0.129*** | +15.53% | +9.07% | **−6.46pp** |

**结果：relmom_top10（纯动量）在 2/3 窗口显著优于 leader∧dist，IC 符号也不稳定（+0.17/−0.08/+0.13）→ 相位门相对纯动量无稳健增量，甚至拖累。**

再用"不属于纯动量 top10 的 leader∧dist 剩余子集"检验相位门是否带来独立信息：

| 窗口 | ld∧dist 不覆盖 relmom-top 的独有部分 |
|---|---|
| W1 | n=219 exc=+2.66% |
| W2 | n=178 exc=+1.90% |
| W3 | n=164 exc=+5.00% |

**相位门独有子集超额仍为正但大幅缩水（+1.9~5.0 vs 原 +4.1~9.1），且显著弱于 relmom_top10** → leader∧distribution 的有效成分大部分来自 20d 相对动量，相位标签贡献的是**有限残余**（1.9-5.0%，三窗方向不稳定）。

## 三、最终意见

**判定依据更新**：红蓝对抗新增决定性证据——`leader∧distribution` 优于全池，主要因为它是相对动量因子的子集，而非"派发期 + 相对强弱"的叠加效应本身。

### 意见（三层）

1. **P0 的定位应从"落地方案"降为"研究确认"**。在证明「相位门相对纯动量的稳健增量」之前（当前 2/3 窗口为负），不宜直接把它接进 `_step5` 作为开仓 gate。否则就是把一个动量因子的皮肤实装成 Wyckoff 信号。

2. **下一动作优先做纯动量对照的完整版**：
   - 用全截面 relmom 分位构建多空/多头因子，计算三窗 IC 稳定性（当前 ±0.08~0.17 已经不稳）；
   - 对 leader∧dist 做**双因子残差**（先剥离 relmom，看 residual 是否仍正）；
   - 若 residual 接近 0 → 直接采用**纯动量排序 + markdown 风控**作为实际生产信号，Wyckoff 相位标签移出决策链。
   - 若 residual 在三窗稳定正 → 才落地 P0 分支（保留轻仓试探缓冲）。

3. **独立于此，值得保留的方案内容**：
   - **P1-1 spring 降级观察**：无论动量结论如何都成立（spring 自身证伪），保留。
   - **P1-2 结构分置信通路关闭**：保留（IC 翻转已证）。
   - **P1-3 置信归一化 + P2 硬编码/死桩**：保留为工程卫生，优先级降低。
   - **markdown 风控闸**：继续作为唯一稳定方向信号（三窗负），不需相位门。

### 一句话结论

> **方案的修改逻辑和工程面是对的（方向合成解耦、RS 前置、flag 门控、A股铁律守卫都成立），但核心 P0 建立的"leader∧distribution 真信号"经纯动量对照证伪了其独立性——它更可能是 20d 相对动量的皮肤。先完成动量残差研究，再把真实 alpha 接到引擎，而不是直接把相位 gate 实装。**
