> 日期：2026-08-07。

---

## 一、总根因：三类信号被错误地混为一个输出

`_step5_trading_plan` 目前把**三个性质完全不同**的东西直接映射成 direction：

| 信号 | 它真正是什么 | 引擎当成了什么 | 后果 |
|---|---|---|---|
| phase（accum/dist/markup/markdown） | **状态描述**（当前处于哪个叙事阶段） | **方向指令** | accumulation 蓄势→买入跑负；distribution 见顶→做空跑反 |
| structural_score | **形态打分**（序列完整度） | **排序器/置信加权** | IC 双窗符号翻转，top/bot 无差甚至反 |
| relative_strength（RS） | **截面相对强弱** | 仅降级（non-leader 降置信） | 唯一正 alpha 被当辅助而非主轴 |

**方法论第一条铁律：状态 ≠ 方向 ≠ 排序，三者必须正交解耦。**

- phase → **只描述，不进方向**
- structural_score → **只存档，不选股**
- RS 才是**唯一可承担方向/选股的轴**

## 二、正确方法论分层（每个信号回到它该在的位置）

### Layer 0 — 市场状态（phase）：叙事上下文，不是预测
- **作用**：告诉交易员"我们处在积累/派发/上涨/下跌的哪个叙事里"，用于时机、风控、仓位语境，**永不直接发多空**。
- **用法**：
  - `markdown` = **全局风控闸**：禁开新多、已有多仓减仓（双窗超额 −3.58/−1.23，唯一稳定负方向）。这是**排除性（exclusion）**，不是进攻性。
  - `distribution` = **顶部预警**：不加仓、准备兑现，但**不做空**（实证反做空错 +0.84/+0.77）。
  - `accumulation` = **关注池**：标的放进 watchlist，等待 spring 触底 + RS 强弱确认，**不构成买入**（蓄势不涨 −1.87/−1.37）。
  - `markup` = **趋势持有语境**：可做多/持有，但使用时须叠加截面 RS 增强。

### Layer 1 — 相对强弱（RS leader）：真正的 alpha 轴
- **作用**：**唯一的截面选股 + 方向强度源**。双窗 p<0.001 / p=0.021，均值 +3.65%/20d，Sharpe ~0.61。
- **正确用法调整（当前是反的）**：
  - 现在：RS 只做"non-leader 时降置信"（负面降级）。
  - 应改：**RS=leader 作为买入电子门（必要条件）**；non-leader → 不进多仓，而不是只降 1 级置信。
- 组合：`leader && 形态触发(spring/sos) && markdown外` 才是完整多仓候选。**RS = 开仓放行，不是旁注。**

### Layer 2 — 触发事件（Spring/SOS/UTAD）：入场的"扳机"，无独立 alpha 原力
- **实证**：spring 个股超额 **−1.44/−3.22（无溢价甚至负）**；研究管线 Spring +3.00%(t=2.02) 是研究频率口径，生产引擎 spring 无溢价。
- 由此：**事件只做"触发时机"（when to act），不做"标的强度"（what to buy）**。
  - spring 定位 = 轻仓试探候选的"时机"，但**标的必须已在 RS=leader 选中**才允许开仓（否则 spring 设为纯观察）。
  - SOS/UTAD 同理，都是时机触发器，方向由 RS 给。
- **教训**：当前 spring+强置信 → 轻仓试探（无 RS 约束）→ 实际超额为负。**必须钉死：spring 定位 = 仅 leader 池内的触发。**

### Layer 3 — 结构分 / 评分：诊断与复盘，不是决策
- **证据**：IC −0.083 ↔ +0.032 符号随窗口翻转 → **跨期非稳定，无排序力**；5× 放大只拉开分布不提高 IC。
- **正确用法**：
  - 存档（复盘"当时序列质量如何"）。
  - **绝不作为买入排序 / 置信度权重**。
  - 若未来要用，需用 **rank-IC + 多窗口符号稳定性门**（|IC|>0.03 且符号一致 N≥3 窗）才有资格，否则丢弃。

### Layer 4 — 风控铁律（A股）：一直保持
- markdown 禁多、distribution 不加仓（已实现）、spring 仅 leader 试探、T+1、涨跌停护栏——这些是守卫，不影响方向。方法论上**这些正确**。

## 三、方法论"组装"：一个正确的决策 DAG

```
             ┌─────────────────────────────────────────────┐
 市场状态(phase) → 叙事上下文：markdown=禁多 / dist=减仓 / accum=watchlist / markup=可持
             └─────────────────────────────────────────────┘
                          |                    |
            Layer1 (选谁)          Layer2 (何时)
        ┌──────────────┐        ┌──────────────────┐
        │ RS=leader ？  │ YES→   │  spring/sos 触发  │──→ 买入候选
        │ 非leader → 不入场 │ NO    │  且 RR≥1.5         │──→ 不入场
        └──────────────┘        └──────────────────┘
              (仅 leader 池)        (等待扳机)
                          |
                     Layer0 markdown 风控闸 → 拒绝 flag
                          |
                   Layer3 structural 存档(不复盘排序)
```

**决策链**：(State 不独用) ∧ (Leader 必须是) ∧ (Event 触发在 Leader 池内) ∧ (RR≥1.5) → 开多。
方向没有被 phase 独立决定，leader 才是方向主来源。

## 四、方法论强弱对照表

| 环节 | 当前（错） | 正确（本方法论） | 依据 |
|---|---|---|---|
| phase | 决定方向指令 | 只做状态/风控/时机上下文 | accum −1.87 / dist 反做空 +0.8 |
| structural_score | 排序 + 置信加权 | 弃用为决策器（仅存档叙述） | IC 符号翻转 |
| RS | 仅降级惩罚 | Leader = 开仓电子门 | 唯一双窗正超额 |
| spring | 独立轻仓试探 | 仅 leader 池内触发 | spring 超额负 |
| 方向生成 | 相位标签直出 | 由"Leader × Event × RR"合成 | — |
| 验证 | 单窗/裸 mu | 双窗/市场中性超额 + 符号稳定门 | — |

## 五、为什么这是"正确"的：三条独立证据链汇合

1. **实证链**：双窗口市场中性超额，leader 唯一稳定正（p<0.001），accum/spring 稳定负，dist 反做空错 → 方向必须来自 RS 而非相位。
2. **理论链**：经典 Wyckoff 的 phase 本就是"状态标签"（P&F 结构色），方向靠事件序列 + 强弱（SOS/Spring 在强势股中才成立）。研究管线 22,148 obs 证实「Spring 只在强标的/正确共振下有溢价」。
3. **工程链**：当前引擎把 phase 当方向是架构性误用（`_step5` phase→direction 直出），修的是认知错位而非再加一个信号。

三者交汇于同一结论：**Wyckoff 的真价值 = 状态叙事(phase) + 截面强弱(RS) + 事件触发(spring) 的正交组合，而当前把三者搅成一个名义分类器。**

## 六、落地方向（对 §六 的延伸）

已落地：accumulation 降档、distribution/markdown 禁做空。
下一步（建议顺序）：
1. **RS 从"降级"升为"电子门"**：`_step5` 开仓分支加 `relative_strength == "leader"` 必要条件（non-leader 一律不入多仓）。这是唯一能立刻把正 alpha 接进交易方向的改动。
2. **spring 触发限定在 leader 池**：spring 轻仓试探 → 仅在 leader 内允许，否则观察。
3. **结构分退出决策**：`_apply_structural_adjustment` 置信加权门禁用（或按 IC 稳定门重开）。
4. 以上均需回归 + 双窗口重验（top30% Sharpe > 全池）。
