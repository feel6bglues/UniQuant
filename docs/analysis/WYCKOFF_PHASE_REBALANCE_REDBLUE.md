## 执行摘要

原始方案（WYCKOFF_PHASE_REBALANCE_IMPLEMENTATION_PLAN.md）的核心诊断正确，但修复方案存在 3 个致命缺陷：

| 缺陷 | 原始方案 | 实证发现 | 裁决 |
|------|---------|---------|------|
| P&F 新阈值过紧 | 积累 0.60/0.80/0.50/0.85 | 99.9% 返回 unknown → P&F 死亡 | **红队胜** |

| Phase 2 放宽 markdown | 门槛从 -5% 改 -2.5% | 链式 markdown 已 47.7%，再放宽=60%+ | **红队胜** |

**唯一正确的修复**: Phase 0 修改 2 — 移除 P&F 覆盖层。这是将 accumulation 从 65.4% 降至 0.4% 的单一最大杠杆（83.8% 的观测中 P&F 可覆盖，98.1% 的覆盖与检测器链分歧）。

### 反事实设计

对每个观测同时运行 2 个引擎：
1. **当前引擎**: `analyze(m)` — P&F 覆盖层正常（`_step1_phase_determine` 中 `pnf_hint` 优先）
2. **链式引擎**: `mock.patch(PointAndFigure.wyckoff_phase_hint → "neutral")` — 覆盖层移除，仅检测器链

二者使用完全相同的月度数据（120 根月线），仅在 P&F 覆盖层上不同。

## Round 1: 计划逻辑/理论层面红蓝对抗

### 议题 1: P&F 覆盖层是积累偏见的首要来源

**蓝队论点（原始方案）**: P&F 积累条件过于宽松（4 项全宽松阈值），派发条件过于严格（4 项全严格阈值），在横盘震荡市场中积累比派发容易满足 4-5 倍，导致 65.9% 的积累率。

**红队反驳**: 没有实证证据表明 P&F 覆盖层是主要驱动因素。检测器链本身也有积累偏好（路径 C 的 `short_trend <= -2%` 门槛极低）。P&F 覆盖层可能只是次要因素。

**实证裁决（蓝队胜）**:
- P&F 提示分布: 65.4% 积累, 18.4% 分布, 16.2% unknown
- 引擎最终相位: 65.4% 积累（与 P&F 提示完全一致）
- 覆盖层移除后: 积累降至 **0.4%**
- P&F 可覆盖率: 83.8% 的观测
- 覆盖分歧率: 98.1% 的覆盖与检测器链分歧（P&F 说积累，链说别的）
- **结论: P&F 覆盖层是积累偏见的绝对主导因素。移除覆盖层是唯一正确的修复方向。**

### 议题 2: 积累检测器过松

**蓝队（原始方案）**: 路径 C 的门槛 `short_trend <= -2% + price < MA20 + MA5 <= MA20 + BC/SC` 让任何短期下跌的股票都被判定为积累。

**红队反驳**: 这可能是 P&F 覆盖层的结果，不是检测器链本身的问题。移除覆盖层后，检测器链的积累率可能很低。

**实证裁决（红队胜）**:
- 覆盖层移除后，链式积累仅 **0.4%**（116/27424）
- 说明检测器链的积累条件 **不是过松，而是过紧**
- 原始方案将门槛从 -2% 收紧到 -5%、从 0.40 收紧到 0.35 会进一步降低积累率至 0%
- **裁决: Phase 1 的方向完全错误。需要的是放松积累检测器，不是收紧。**

### 议题 3: Markup/Markdown 方向反转原因是检测滞后

**蓝队（原始方案）**: Markup 在已涨 3%+ 时才确认 → 已是顶部 → 后续收益 -4.17%。Markdown 在已跌 5%+ 时才确认 → 已是底部 → 后续收益 +3.45%。修复方向是将检测点前移。

**红队反驳**: 方向反转可能是 P&F 覆盖层导致的。P&F 将大量积累分配给本应为 markup 的观测，导致 markup 样本被稀释。覆盖层移除后，方向反转可能自然消失。

**实证裁决（红队部分胜）**:
- 当前世界: markup -0.84%, markdown +1.67% — 反转（p=0.9968 ❌）
- 链式世界: markup **-1.52%**, markdown **+2.25%** — 反转持续（p=1.0000 ❌）
- **方向反转不是 P&F 覆盖层导致的，而是检测器链自身的结构性问题**
- 红队部分正确（反转不是覆盖层导致的），但蓝队的基本诊断正确（检测滞后是原因）
- **裁决: 检测滞后诊断正确，但 Phase 2 的放宽阈值方案需要重新设计**

### 议题 4: 方向反转的时段稳定性

**蓝队**: Phase 2 的修复（降低门槛到 1%）将使 markup 提前捕获上涨段，方向反转自然解决。

**红队**: 方向反转可能只是特定市场环境（2022-2024 熊市）的统计假象。在 2020-2021 牛市中，markup 收益可能是正的。

**实证裁决（红队胜）**:
| 时段 | n | markup 均值 | markdown 均值 | 反转? |
|------|---|------------|--------------|-------|
| 2020-2021 | 9426 | +0.22% | +6.24% | ✅ (markdown 大幅反转) |
| 2022-2023 | 11127 | -3.44% | +0.02% | ✅ (markup 反转) |
| 2024 | 2475 | -5.56% | -5.63% | ❌ (双负, 系统熊市) |
- **方向反转具有强烈的时段依赖性**。2020-2021 牛市中 markup 略正，markdown 大幅正（反弹）。2022-2023 熊市中 markup 大幅负，markdown 中性。
- 简单降低门槛不能解决时段依赖性问题。需要更复杂的机制（如条件于市场状态）。

## Round 2: 统计方法论层面红蓝对抗

### 议题 5: 阈值设定的过拟合风险

**蓝队**: 阈值设定基于 Wyckoff 经典理论和 A 股市场经验，具有理论依据。

**红队**: 原始方案中所有阈值（0.6/0.80/0.50/0.85/down_ratio<0.45 等）都是从同一数据集（254K 观测）中手动调优得出的。没有 hold-out 验证，没有 walk-forward 测试。**这是典型的 in-sample 过拟合**。

**实证裁决（红队压倒性胜）**:
- 新阈值在 27K 独立样本上验证: **99.9% unknown**
- bootstrap CI: 积累 0.00% [0.00%, 0.00%], 分布 0.15% [0.11%, 0.19%]
- 阈值设定导致了 P&F 提示完全死亡
- **裁决: 过拟合风险极高。需要 3-way 数据分割（训练/验证/测试）和 walk-forward 阈值选择。**

### 议题 6: 预期指标变化的统计可信度

**蓝队**: 预期 Phase 0 将积累从 65.9% 降至 45-50%，Phase 1 降至 25-30%，Phase 2 将 markup 从 3.6% 提升至 15-20% 并将收益从 -4.17% 反转为 +3~8%。

**红队**: 这些预期指标没有置信区间，没有统计检验。例如 "markup 收益 +3~8%" 的区间宽度达 5 个百分点，没有 bootstrap 验证，没有时段稳定性测试。

**实证裁决（红队胜）**:
- bootstrap CI 显示链式 markup 收益: -1.52% [-2.19%, -0.82%] — 显著为负
- 95% CI 的上限是 -0.82%，与 +3% 相距甚远
- 时段分析显示 2022-2023 年 markup 收益 -3.44%，2024 年 -5.56%
- 原始方案声称的 "+3~8%" 在当前数据中不可实现
- **裁决: 所有预期指标需要 bootstrap CI 和 walk-forward 验证。当前预期值过于乐观。**

### 议题 7: 反事实验证的充分性

**蓝队**: 原始方案提出"每次修改后运行 1000 只验证"。

**红队**: 这只能验证实现后的效果，不能验证各个修改的独立贡献。原始方案将 Phase 0 的两个修改（阈值收紧 + 覆盖层移除）捆绑在一起，无法区分各自效果。

**实证裁决（红队胜）**:
- 通过 monkeypatch 反事实，我们分离了覆盖层移除的效果（积累 65.4% → 0.4%）
- 但没有分离阈值收紧的效果，因为新阈值导致 P&F 死亡
- 需要一个中间步骤: 先用当前阈值移除覆盖层，再逐步调整阈值
- **裁决: 需要分步验证，每个修改独立测试。**

## Round 3: 实现可行性/回归风险红蓝对抗

### 议题 8: 覆盖层移除对现有测试的影响

**蓝队**: 132 个 classic_wyckoff 测试全部通过。

**红队**: 移除覆盖层将改变几乎所有 accumulation/distribution 测试的相位输出。许多测试依赖于 P&F 覆盖层来产生特定的相位结果。这些测试会失败。

**实证裁决**: 未直接验证，但基于数据:
- 83.8% 的观测中 P&F 可覆盖
- 98.1% 的覆盖与检测器链分歧
- 这意味着几乎所有依赖 P&F 覆盖层的测试都会失败
- 需要大量测试重写
- **裁决: 回归风险高。需要先运行测试确认失败范围，再逐用例修复。**

### 议题 9: 检测器链 markdown 偏见的来源

**蓝队（原始方案）**: 未识别 markdown 偏见问题。Phase 2 的降低门槛会使 markdown 更容易触发。

**红队**: 如果 markdown 已占 47.7%，降低门槛会使 markdown 占 60%+。需要先诊断 markdown 偏见的来源。

**实证裁决（红队胜）**:
- 链式 markdown 47.7% 的分布: 路径 1 (TR 外) 和路径 2/3 (BC 跌破) 的贡献
- 需要分解每个路径的触发频率
- 最可能的原因是路径 1 的 `short_trend <= -5% AND price < MA20*0.95` 在 120 月线中过于宽松
- **裁决: 在实现 Phase 2 之前，需要先收紧 markdown 检测器。Phase 2 的方向完全错误。**

### 议题 10: 实现复杂度与风险

**蓝队**: 5 个 Phase 独立实现，可回滚。

**红队**: 实际依赖关系更复杂: Phase 0 必须最先完成，但 Phase 1 需要重新设计（方向反转），Phase 2 需要先收紧 markdown 再放宽 markup。修改后的依赖图:

```
Phase 0 (覆盖层移除) → 诊断各检测器分布 → Phase 1new (放松积累)
                                              → Phase 2new (收紧 markdown, 放宽 markup)
                                              → Phase 3old (转换检测)
                                              → Phase 4old (置信度重算)
                                              → Phase 5old (调仓优化)
```

依赖关系从线性变为分支式，增加了实现复杂度。

**裁决**: 红队正确。需要重新制定依赖图和实现顺序。

## 修正方案: Wyckoff 相位再平衡 v2.0

### 核心理念

1. **P&F 覆盖层必须移除** — 这是唯一实证验证有效的修复
2. **检测器链需要重新平衡** — 不是简单收紧或放宽，而是先诊断再调整
3. **阈值设定必须基于数据** — 3-way 分割 + walk-forward 验证
4. **方向反转是结构性问题** — 需要预测性检测，不是滞后确认

### Phase 0: P&F 覆盖层移除 + 阈值校准（修改 v2）

**修改 1: 移除 P&F 覆盖层**（同原始方案修改 2）
- 在 `_step1_phase_determine` 中，P&F hint 不再覆盖检测器链
- 改为仅记录分歧
- 这是唯一经过实证验证的修复

**修改 2: P&F 阈值校准**（替代原始方案修改 1）
- 新阈值的校准目标: 积累 30-40%, 分布 20-30%, unknown 30-50%
- 基于数据驱动校准，非理论推导
- 校准脚本: `v9_rb_validation.py` 的 `proposed_phase_hint` 函数，参数化搜索

**建议的新阈值**（基于 27K 观测的初步搜索）:
```python
# 积累: 小幅收紧
accum_cond = (
    rising_lows_ratio > 0.55       # 原 0.5, 改 0.55
    and range_contraction < 0.83   # 原 0.85, 改 0.83
    and recent_rising_lows > 0.45  # 原 0.4, 改 0.45
    and avg_recent < avg_early * 0.88  # 原 0.9, 改 0.88
    and down_ratio < 0.48          # 新增: 下降列比例 < 48%
)

# 分布: 小幅放宽
dist_cond = (
    falling_highs_ratio > 0.30     # 维持 0.30
    and (
        range_contraction > 1.18   # 原 1.2, 改 1.18
        or avg_recent > avg_early * 1.08  # 原 1.1, 改 1.08
    )
    and down_ratio > 0.47          # 原 0.5, 改 0.47
    and rising_lows_ratio < 0.55   # 维持 0.55
)
```

### Phase 1: 检测器链重新平衡（重写替代原始 Phase 1）

**目标**: 链式相位分布: 积累 10-15%, markup 15-20%, 分布 10-15%, markdown 15-25%, unknown 25-40%

**修改 1: 放松积累检测器**（当前 0.4% → 目标 10-15%）
```python
# 路径 B (TR 内): 降低 prior_trend 门槛
if ctx["is_in_trading_range"]:
    if ctx["prior_trend_pct"] < -0.02:  # 从 -0.03 放宽到 -0.02
        return {"phase": WyckoffPhase.ACCUMULATION}
    if ctx["relative_position"] <= 0.45 and rule0.bc_found:  # 从 0.40 放宽到 0.45
        return {"phase": WyckoffPhase.ACCUMULATION}

# 路径 C (TR 外): 降低 short_trend 门槛 + 移除 MA5 < MA20 约束
else:
    if (
        ctx["short_trend_pct"] <= -0.01  # 从 -0.02 放宽到 -0.01
        and ctx["current_price"] < ctx["ma20"]  # 维持
        and (rule0.bc_found or rule0.sc_found)  # 放宽: 任一即可
    ):
        return {"phase": WyckoffPhase.ACCUMULATION}
```

**修改 2: 收紧 markdown 检测器**（当前 47.7% → 目标 15-25%）
```python
# 路径 1 (TR 外): 增加条件
if st <= st_max and cp < ma20 * cp_below_ma:
    # 新增: 必须有放量确认
    if len(df) >= 5:
        vol_5 = float(df.tail(5)["volume"].mean())
        vol_20 = float(df.tail(20)["volume"].mean()) if len(df) >= 20 else vol_5
        if vol_20 > 0 and vol_5 > vol_20 * 1.1:  # 放量下跌确认
            return {"phase": WyckoffPhase.MARKDOWN}
```
**注意**: 与原始方案相反，这里抑制 markdown 触发，而非放松。

**修改 3: 放宽 markup 检测器**（当前 16% → 目标 15-20%，收益从 -1.52% 改善）
```python
# 新增早期路径: short_trend > 0.5% 即触发
if st >= 0.005 and cp > ma20 and ma5 >= ma20 * 0.98:
    return {"phase": WyckoffPhase.MARKUP}
```

### Phase 2: 方向反转修复（替代原始 Phase 2）

**核心问题**: markup 收益 -1.52%, markdown 收益 +2.25% — 检测器滞后确认导致反向收益。

**修复方案**: 引入**预测性检测**，基于以下信号:
1. markup 早期信号: 积累→markup 转换（price 刚站上 MA20 + 温和放量 + 短期趋势转正）
2. markdown 早期信号: 分布→markdown 转换（price 刚跌破 MA20 + 短期趋势转负）

**关键差异**: 不是简单降低门槛，而是检测**转换点**。

```python
# 早期 markup 检测
def _detect_early_markup(self, df, ctx, rule0, previous_phase=None):
    if previous_phase != "accumulation":
        return None
    if (ctx["short_trend_pct"] > 0.005
        and ctx["current_price"] > ctx["ma20"]
        and ctx["ma5"] > ctx["ma20"]):
        return {"phase": WyckoffPhase.MARKUP}
```

### Phase 3: 相位转换检测 + 置信度重算（保留原始方案）

**保留原始方案 Phase 3+4 设计**，但:
- 转换检测的置信度加分基于新相位分布（积累 10-15%, markup 15-20% 等）
- 位置置信度的阈值基于新相位分布校准
- 需要 walk-forward 验证

### Phase 4: 调仓策略优化（保留原始方案 Phase 5）

**保留原始方案 Phase 5**，但:
- 换手率优化基于新相位分布
- 转换驱动调仓基于 Phase 3 的转换检测

### 验证方法论

1. **3-way 数据分割**: 2020-2021 (训练) / 2022-2023 (验证) / 2024 (测试)
2. **阈值搜索**: 在训练集上网格搜索，验证集上选择最佳，测试集上报告最终结果
3. **bootstrap 验证**: 每个指标报告 95% CI，非点估计
4. **walk-forward 验证**: 每次修改后运行 1000 只验证，确认指标改善
5. **回归测试**: 132 个 classic_wyckoff 测试全部通过（测试用例可能需要更新）

### 回滚方案

同原始方案: 每个修改独立 commit，可按 commit 回滚。新增 calibration 开关:

```yaml
wyckoff:

    enabled: false
    pnf_override_removed: true       # Phase 0: 覆盖层移除
    pnf_thresholds_v2: false         # Phase 0: 新阈值（默认关闭，需校准）
    accum_loosened: false            # Phase 1: 放松积累
    markdown_tightened: false        # Phase 1: 收紧 markdown
    markup_loosened: false           # Phase 1: 放宽 markup
    early_markup: false              # Phase 2: 早期 markup
    transition_detection: false      # Phase 3: 转换检测
```

## 结论

原始方案识别了正确的问题（P&F 覆盖层导致的积累偏见），但修复方案存在 3 个致命缺陷:
1. P&F 新阈值过紧导致 P&F 死亡
2. Phase 1 方向错误（需要放松而非收紧积累）
3. Phase 2 方向错误（需要收紧而非放宽 markdown）

红蓝对抗验证揭示了:
- 覆盖层移除是唯一有效的修复，积累 65.4% → 0.4%
- 检测器链也有严重偏见（markdown 47.7%）
- 方向反转是结构性问题，非简单门槛调整可解决
- 所有阈值设定需要 walk-forward 验证

**修正方案 v2.0** 保留了覆盖层移除，重新设计了检测器链平衡，引入了预测性检测，并采用 3-way 数据分割的验证方法论。
