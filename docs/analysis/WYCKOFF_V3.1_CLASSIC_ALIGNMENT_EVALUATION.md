**v3.1 方案预期分布**（链式引擎 + rp=0.15）:

### 2.3 事件序列驱动

**研究管线方法**（`wyckoff_research_report.md` §4-5）:
- 先检测 8 类事件（PS/SC/AR/ST/SOS/LPS/Spring/JAC）
- 用 WSO 经验权重累加事件评分
- 相位由事件序列决定（WSO ≥ 0.04 → 买入，≤ -0.03 → 卖出）
- 不依赖"phase"标签做交易决策，依赖事件序列本身

**v3.1 方案方法**:
- 仍使用检测器链 winner-takes-all（markup→distribution→markdown→accumulation→spring→utad→sos）
- 相位仍由 MA 趋势和价格位置决定，非事件序列
- 事件检测（`events.py` 的 `detect_all_events`）存在但未被用于相位判定

**评估**: ❌ 未对齐。v3.1 未改变检测器链架构。根本问题——相位是"过去描述"而非"未来预测"——未解决。研究管线证明事件序列在 A 股具有统计显著的预测力（t=10.24），但 v3.1 未接入事件序列。

### 2.4 三周期共振

**研究管线方法**（`wyckoff_research_report.md` §3-6）:
- 月线/周线/日线独立分类
- 三周期共振过滤（反向指示性）
- 最强子策略: WSO 买入 + bearish 共振 = +2.83% (t=7.32)
- 最重要发现: 三周期共振是**反向指示**——全部看多时是顶部

**v3.1 方案方法**:
- 仅在月线周期进行相位判定
- `MultiTimeframeResonance` 类已实现且有测试，但未用于相位判定
- 无共振过滤

**评估**: ❌ 未对齐。三周期共振是经典 Wyckoff 分析的核心，也是研究管线成功的关键因素。v3.1 完全未涉及。

### 2.5 置信度体系

**研究管线方法**（`wyckoff_research_report.md` §6）:
- WSS 统计评分（180 种事件序列，f6 校准）
- 连续评分（t 统计量 × 收益均值 × 胜率）
- 评分分布有意义，各档 fwd 收益单调

**v3.1 方案方法**:
- 未修改置信度体系
- 当前置信度 84% D 档，0% A 档
- 3 值离散，无区分度

**评估**: ❌ 未对齐。WSS 评分已在 `WyckoffScorer` 中实现且有 436 种序列的查找表，但默认关闭。v3.1 未启用。

### 2.6 相位转换

**研究管线方法**（`WYCKOFF_MULTI_PERIOD_VALIDATION_20260803.md` §2）:
- 当前引擎最大的问题是 accumulation↔distribution 双向混淆（74+63 次）
- 正确转换率 39.6%（低于随机 50%）
- 需要事件序列驱动来消除混淆

**v3.1 方案方法**:
- 未修改检测器链，accumulation↔distribution 混淆未解决
- 覆盖层移除后 accumulation 仅 0.6%，混淆问题"消失"但方式不对——因为积累几乎不产生了

**评估**: ❌ 未对齐。混淆被"掩盖"而非"解决"。仅 0.6% 的 accumulation 不是正常分布，而是检测器链优先级问题的结果。

### 2.7 Spring→买入传导

**研究管线方法**（`wyckoff_research_report.md` §4.3）:
- Spring 是最强的单一正向事件（+3.00%, t=2.02）
- Spring 单独使用效果优于 Spring + 事件链
- 研究管线将 Spring 视为独立买入信号

**v3.1 方案方法**:
- 未修改 Spring→买入的传导逻辑
- 全量扫描显示 66 只 Spring 标的 0 只给出"买入"方向

**评估**: ❌ 未对齐。Spring 是经典 Wyckoff 最强的买入信号，但引擎从不将其转化为买入指令。v3.1 未处理此问题。

## 4. 差距根因分析

### 4.1 核心差距：v3.1 解决的是"量"的问题，不是"质"的问题

v3.1 修复的是**分布偏差**（accum 太多、markdown 太多），但未修复**相位质量**（相位不预测未来方向）。

| 问题类型 | 问题 | 是否被 v3.1 解决 | 证据 |
|---------|------|----------------|------|
| 量的问题 | accumulation 63.2% | ✅ 降至 0.6% | 覆盖层移除 |
| 量的问题 | markdown 46.4% | ✅ 降至 11.4% | rp 约束 |
| 质的问题 | markup 方向错误 | ❌ -1.55% 仍错误 | 关联研究管线 |
| 质的问题 | distribution 方向错误 | ❌ +1.40% 仍错误 | 同上 |
| 质的问题 | 理论一致性 50% | ❌ ~55% 仍低于 65% | 差距未消除 |
| 质的问题 | 相位是过去标签非未来预测 | ❌ 架构未改 | 检测器链不变 |

### 4.2 4 个架构错误仅修复了 1 个

| 架构错误 | 描述 | v3.1 修复状态 |
|---------|------|-------------|
| 错误一 | 相位是"标签"非"预测" | ❌ 未修复 |
| 错误二 | 检测器链 winner-takes-all | ❌ 未修复 |
| 错误三 | PnF 主导（实际已修复但未替换） | ⚠️ 覆盖层移除（移除 PnF，但未替换为事件序列） |
| 错误四 | 无共振过滤 | ❌ 未修复 |

### 4.3 研究管线已验证的路径未被采用

研究管线（`scripts/wyckoff_multitf/`）已经通过了 22,148 观测的实证验证，证明了：
- 事件序列评分（WSO）在 A 股有效（t=6.25 买入，t=-10.90 卖出）
- 共振过滤增强信号（+0.50% 买入增益，-0.34% 卖出增益）
- Spring 独立买入信号最有效（+3.00%, t=2.02）
- 卖出信号强于买入信号 3 倍（均值回归主导）

但 v3.1 采用的方法是**移除 PnF 覆盖层 + 添加 rp 约束 + 添加市场状态**，而不是**接入研究管线已验证的事件序列 + 共振 + WSS 体系**。

## 5. 建议的修复路径

### 5.1 短期：v3.1 方案（1-2 天）

v3.1 的 3 处修改仍有价值，因为它们消除了**最明显的分布偏差**：
1. 移除 P&F 覆盖层（accum 63.2%→0.6%）
2. Markdown rp≥0.15 约束（方向+2.27%→-0.55%）
3. 市场状态自适应（牛市 markup +4.61%）

**预期效果**: 理论一致性从 50% 提升至 ~55%，markdown 方向修复。

### 5.2 中期：接入研究管线已验证的组件（3-5 天）

**P0: 重写检测器链为三周期 + 事件序列投票制**（`WYCKOFF_QUANT_TO_CLASSIC_ROADMAP_20260803.md` §3.2 P0）
- 移除当前 7 检测器 winner-takes-all
- 实现月线/周线/日线独立分类
- 事件序列投票决定相位
- 预期: 理论一致性 50%→65%

**P1: 启用 WSS 评分**（`WYCKOFF_QUANT_TO_CLASSIC_ROADMAP_20260803.md` §3.2 P1）
- `WyckoffScorer` 已实现 + 436 种序列查找表
- 默认开启 WSS
- 预期: 置信度分布有意义，各档 fwd 收益单调

**P2: 共振过滤接入交易决策**（`WYCKOFF_QUANT_TO_CLASSIC_ROADMAP_20260803.md` §3.2 P2）
- `MultiTimeframeResonance` 已实现且有测试
- 接入 `_build_report` 和 `_step5_trading_plan`
- 预期: 消除相位冲突信号

### 5.3 长期：Spring→买入传导修复（1-2 天）

**P3: 修复 Spring→买入信号门控**
- 排查 `_step5_trading_plan` 的信号门控逻辑
- Spring 检测到后应直接给出买入信号（研究管线证明 +3.00%, t=2.02）

## 6. 结论

**v3.1 方案是必要的但不足够的修复。**

它修复了生产引擎最明显的分布偏差（accum 63.2%→0.6%, markdown 方向修复），但未触及 4 个架构错误中的 3 个。理论一致性预计从 50% 提升至 ~55%，但目标是 65-70%（研究管线已验证的水平）。

**核心问题**: v3.1 仍在"修复现有的错误引擎"，而研究管线已经指出了"正确的引擎应该怎样做"。研究管线使用**事件序列驱动 + 三周期共振 + WSS 统计评分**，在 22,148 观测上达到了 t=10.24, Sharpe 2.02。生产引擎只需对齐这个已验证的路径，而不是从零开始设计新的修复方案。

**建议**: 在 v3.1 修复后，立即启动研究管线对齐（中期 3-5 天），将已实现的 WSS/MultiTimeframeResonance 组件接入生产决策流程。
