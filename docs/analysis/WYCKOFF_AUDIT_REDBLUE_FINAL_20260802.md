## 2. Round 1 — A1 WSS / A2 MTF 深度对抗

### A1 WSS 死链：红方攻击 + 蓝方辩护

**红方（质疑"修复有价值"）：**
- WSS 权重稳定序列（n≥50）中 wss>0 仅 24/65（v1）、72/188（v2），且正上限仅 +0.09。
- `SOS>SOS` wss=-0.19、`SC>SC>AR>SOS>SOS` mean=-3.1%——训练数据本身大部分是负/零 alpha。
- **即使接线，可能让 structural_score 更低而非更高。**

**蓝方（辩护修复动机）：**
- WSS 价值在**排序区分度**（权重范围 [-0.19, +0.09] 比 WSO 的 [-0.03, +0.1] 更宽），扩大方差使 ≥70 阈值可达。
- 数据格式完全兼容（seq_key 都是 `'>'.join`），是**纯接线遗漏**非设计问题。
- `phase6_wss_scoring.py` 用 f6 前向收益 t 统计量——有实证校准。

**裁决：** A1 成立（接线遗漏确凿，修复成本低），但**红方追加须纳入修复验证**：接线后需校验 f6 口径与生产数据一致，且确认 WSS 不会系统性拉低评分。**修复 = 接线 + 有效性再验证，非纯接线。**

### A2 MTF 双实现：表述修正

**红方攻击修正：** `MultiTimeframeResonance` 有 `test_phase_analysis.py` 8 个测试（resonance/resonance_strength 全测），称"死代码"不准确。

**蓝方：** 引擎 import 的是 `RegimeAwarePhaseClassifier`（`engine.py:71`），生产融合走 `analysis.py:196` rule9。共振类与生产路径无调用关系。

**裁决：** A2 成立但表述修正为"**共振模块有测试覆盖但引擎生产路径使用独立的 rule9 融合，存在两套口径并存**"。这是设计意图分歧（投票 vs 规则覆盖），非纯粹死代码。

## 3. Round 2 — A3 量能 / A4 LPS / A5 置信度

### A3 量能参照系：红方攻击成功，降级

实证（000001.SZ）：`_scan_spring` 用 median、step3 转 rule1 用 rolling mean，median/mean=0.917，偏差 8%。
- vol_ratio=0.7（median 萎缩）→ rule1 判"萎缩" ✅
- vol_ratio=0.8（median 萎缩）→ rule1 判"平均" ⚠️ 语义反（缩量标为"平均"，再被 step3 打"一级(放量确认)"）

**裁决：** 报告"缩量被叫放量"夸大一档。实际是 **vol_ratio∈[0.7,0.8] 窄窗口的缩量被标为"平均"**。B 级问题，非 A 级。但**统一参照系**的建议仍然有效。

### A4 LPS 传导：红方深化根因（最重要修正）

**实证（65 只可验证 spring 标的，rule6 逐条件分解）：**
- **low_volume 失败率 92%**（`recent_vol < max_vol×0.3`，用整段 max_vol 作分母）
- price_held 失败率 68%（整段 min 作门槛）
- bounce 失败率 32%
- 三因全部满足 = 0 只 → LPS 0 通过
- tail_skip（spring 太近尾部）仅 1.5%，剩余 K 线中位数 18 根

**红方攻击（报告根因归因不完整）：** 报告说"三条件 AND 过严"，但未点名**最致命的 low_volume 的 max_vol 分母统计陷阱**——post_spring 窗口内只要 1 根放量（ST/反弹），max_vol 拉高，recent_vol 需 < 其 30%，正常波动几乎不可能。

**蓝方（为报告辩护）：** 报告 A4 建议指向 `WYCKOFF_LPS_REFACTOR_DESIGN_20260802.md`，该设计**已完整覆盖此根因**——`spring_volume` 参数、`test_vol_ratio = test_bar_volume / spring_volume`、明确标注"旧：recent_vol < max(post_spring_vol) × 0.3 ← 参照系错误"。

**裁决：** A4 报告方向正确，但**需补充定量根因**（low_volume 92% 是主因）。重构设计文档本身无缺陷。**修复优先级：A4 应列为最高**——它直接决定 spring→LPS→做多传导链能否打通。

**红方附加发现（ETF 污染）**：66 只 spring 中 **6 只（9.1%）是 ETF**（159605/159896/159966/161037/161908/166107）——ETF 采用 T+0 且无个股 10% 涨跌停，其 spring 检测与个股混用导致样本不纯。spring→LPS 传导率 0 的评估应排除 ETF 后重算，以避免低质量样本稀释证据。

### A5 置信度：完全确认

`_calc_confidence` 5 条件矩阵 → A/B+/C/D 离散级 → 扫描映射 0.9/0.7/0.5/0.3。D 占 84% 因大多数标的达不到矩阵门槛。报告论断成立，无需修正。

## 4. Round 3 — structural_score / P0 / 文档漂移

### 4.1 structural_score：红方重大升级发现

**决定性根因**：`_compute_structural_score` 的**数学上限 = 65.7 分**：
- WSO 全正权重和仅 0.0334
- + 最大序列 bonus 0.03 + phase bonus 0.15 + event bonus 0.10 = max raw 0.3134
- → 映射上限 (0.3134+1)/2×100 = 65.7

**扫描数据 max=64.43 与之吻合**。≥70 升级阈值**在数学上不可能达到**——不是分布拥挤问题，是**评分函数权重天花板**。

**红方升级攻击（报告未揭示的最严重问题）**：`tests/classic_wyckoff/test_structural_score.py` 的 `test_adjustment_high_upgrades_level`（line 158）**直接注入 80.0 分**验证"≥70 升级"逻辑——但生产 pipeline 永远产不出 ≥70 分。**这是"测试绿但功能死"**：测试验证函数契约，不验证生产可达性。SQ-C1 的置信度升级路径在生产中是**结构性死代码**。

**裁决：** 报告"区分度差"正确但**不够彻底**——这是设计缺陷（权重天花板 + 阈值不匹配），非分布偶然。修复需二选一：放宽权重映射（WSS 加载可扩方差）或下调阈值。

### 4.2 P0 修复真实性：确认

- PF-C1/C2/C3 接线、PH-C1/C2 事件序列、ES-C1/C3 共享扫描器、CF-C4 假突破、CN-C4 复权探测——全部源码特征 + 行为双重验证通过。
- 但**红方附加发现**：P&F hint 明确时相位 100% 一致（0 不一致），即 **63.2% 标的（3404/5382）的相位由 PnF 启发式独占**（`wyckoff_phase_hint` 的 rising_lows/range_contraction 简单条件），7 检测器链只在 36.8% 标的上运行。
- 这与"相位-收益背离"（accum 6m -21%、dist 1m +6.9%）是**同一因果链**：PnF 启发式判的"吸筹"实际是"低点抬升+区间收窄"（趋势转涨特征），判的"派发"是"区间扩大+下跌"（已下跌特征）——**是过去形态的统计描述，非前瞻信号**。

### 4.3 文档漂移：确认且比报告更严重

VERIFICATION_v1 验收总表**4 项 P0 核心**（ES-C3/PH-C1/PH-C2/CF-C4）状态列标 FAIL，实跑全 PASS。报告只列举了 ES-C3/CF-C4，实际 PH-C1/PH-C2 也在漂移清单。

## 6. 结论

审计报告是**可信的工程诊断**，但其"修复建议"指向的每个问题背后都有更深的结构性根因（红方发现的）：LPS 的 max_vol 统计陷阱、SQ-C1 的权重天花板、PnF 启发式的历史形态本质、WSS 训练-推理断裂。

**Wyckoff 引擎的现状**：检测层（事件识别）合格，决策层（LPS/置信度/评分）断裂，分类层（相位）反映过去而非未来。若目标是研究平台，检测层与 WSS 校准组件可继续投入；若目标是交易信号，需先打通 A4（LPS）传导链并重做相位前瞻校准，否则任何信号都不具备可交易性。
